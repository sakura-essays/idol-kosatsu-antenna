# 自動発掘と記事収集

## 実行間隔

GitHub Actions の `Collect, discover and publish` は6時間おきに動きます（日本時間の03:43、09:43、15:43、21:43が目安）。A・Bと既存フィードは原則毎回、適格記事が少ないCの新規フィードは原則2日おきに取得します。同日の最初の収集で書き手を探索します。候補のフィード検証は探索に続けて行い、候補の重複や過去の検証結果を引き継ぎます。UTCの日付を処理単位に使います。公開本文は各収集回に最大300本を処理します。期限を迎えた再試行、最近の投稿、内容の手掛かりがある記事から順に着手します。手動実行でも同じ間隔制御を適用します。

`config/discovery.json` の探索先は公開タグ、新着一覧、検索からの初期候補です。本文中のリンクと公開記事ページの関連リンクも使います。探索履歴を引き継いでタグと媒体を巡回し、週ごとの系列別の登録状況を優先順位に反映します。ブログではプロフィールかトップページに広告されたRSS・Atomを優先します。robots.txt、HTTPS、ホスト単位の間隔、タイムアウト、4MB上限、429・503の再開時刻を守ります。アクセス制限のあるAPIや有料部分は利用しません。AmebaのRSS専用ホストでrobots.txtだけが403を返す場合は、RFC 9309 §2.3.1.3に沿って公式RSSのパスだけを対象にします。フィード自体のアクセスエラーは再試行対象です。[Amebaの公式案内](https://ameblo.jp/staff/entry-12865036798.html)・[RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3.1.3)

## 自動登録と掲載

- Aはサンプル内に適格記事が複数あり、半数以上が適格。Bは複数の適格記事とその他の記事が混在。Cは1本を確認。Dにはまだ記事を確認できない候補や取得できない候補を含め、内部で再探索します。書き手の分類は取得した内容と成否から更新されます。
- RSSの題名、本文・要約、タグ、記事内の具体的な文脈を優先します。題材と本人の観察が明確な短文も対象です。過去の傾向は記事内の根拠を補います。人気・更新頻度・AI利用の推定は掲載判定に入りません。
- 根拠が弱い場合は公開本文とタグから再判定します。初回の公開本文確認に着手した後の再試行は通常1・2・3日間隔で最長7日。大量移行で初回未着手の件数は別途記録します。通信障害は最長21日の例外を設けます。期限で非掲載にした記事は理由を記録し、内容や判定ルールが変われば再評価します。
- 公開3日以上経過した適格記事は、UTC日ごとに最大140本、書き手ごとに5本まで追加します。新着順は元の公開日時を使います。追加日時は管理データの `site_added_at` に保存します。
- 掲載条件とピックアップの選考は独立しています。本文・画像・有料部分は公開データやリポジトリに保存しません。

## 管理と復旧

- `state/status.json` の `metrics` とActionsの要約に、有効なフィード数、媒体・系列・分類別の登録状況、新規発見・登録、再判定、失敗、判定理由を記録します。手動確認発生率の分母は当該回で結果が変わった記事、自動掲載率の分母は当該回で自動掲載・自動非掲載が確定した記事です。
- `state/discovered-sources.json` は自動登録された書き手、`state/discovery-candidates.json` は候補と再調査の理由、`state/discovery.json` は探索履歴です。`state/review.json` は運営者の指定など、明示的な手動確認だけを記録します。通常の判定保留は運営者の作業を待たず進みます。
- 掲載停止は `config/moderation.json` の `blocked_urls` と `blocked_authors` へ追加します。書き手IDまたはプロフィールURLで止められます。記事の明示的な除外・承認を優先します。
- フィード一部失敗でも過去記事を保持して更新します。継続的に失敗するフィードは有効数から外し、段階的な間隔で再試行します。収集やビルドが途中で止まった場合はGitHubの前回コミットと公開済み版が復旧点になります。同時変更と競合したpushは上書きせず、次回は最新mainから処理します。
- 自動掲載を停止するには `config/publication.json` の `enabled` を無効にします。障害調査では該当するソース・設定コミットをrevertし、生成済みファイルは最新の蓄積から再ビルドします。
